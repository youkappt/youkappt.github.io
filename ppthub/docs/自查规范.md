# PPT 术语图鉴 · 自查规范（Self-Check Spec）

> 目标：每次增删术语 / 改 demo / 调分类后，按本规范过一遍，避免「重复」「悬空引用」「demo 运行时报错」三类经典事故。  
> 适用范围：`ppthub/` 子页（纯静态，数据在 `data.js` / `demos.js` / `terms-extra.js`）。  
> 维护：2026-07-26 初版。新增术语的固定工序见末尾「新增术语标准工序」。

---

## 0. 一条铁律

**改完必须跑自动化自检，全绿才算完。** 人工肉眼看不出「related 指向不存在的 id」「demo 初始 render 分支缺失」「重复 name」这类问题——它们只在脚本里暴露。

## 1. 自动化检查（必跑，纯命令）

### 1.1 语法检查（所有 JS）

```bash
cd ppthub
node --check data.js demos.js terms-extra.js app.js
```

### 1.2 数据完整性 + 静态自检

```bash
node tests/verify_ppthub.js
```

覆盖 12 项（详见脚本注释；语法检查经 `node --check` 单独进行，不计入此 12 项）：

1. `data / demos / terms-extra` 三者数量一致
2. 无重复 `id` / 无重复 `name`（精确，含已删除重名的坑）
3. 每个 `term.demo` 在 `DEMOS` 中有实现
4. 无孤立 demo（`DEMOS` 有定义但无 term 引用）
5. `related` 全部指向已存在 term（无悬空）
6. `category` 均在标准白名单（10 类）内
7. `EXTRA` 无孤儿 key、必填字段 `pitfall`/`mnemonic` 齐全
8. 反模式 `textAlign:flex-start` 无残留（非法值，应为 `left`/`center`/`right`）

### 1.3 demo 运行时真实执行（抓运行时 bug）

```bash
# jsdom 在 WorkBuddy 托管 node 工作区，需指定 NODE_PATH
NODE_PATH=/Users/youka/.workbuddy/binaries/node/workspace/node_modules \
  node tests/demo_runtime_test.js
```

- 用 jsdom 起真实 DOM，`window.eval` 同 `<script>` 上下文
- 逐个调用 `DEMOS[key](container)`，再模拟点击每个 `data-m/data-g/data-a/data-op/data-c` 按钮
- 抓：运行时报错 / 空渲染 / 未定义函数调用
- **实现细节（重要）**：每个 demo 调用前清空 `document.body`，否则多个同名 id（`#stage/#s/#efStage…`）在 body 累积会触发 jsdom `querySelector` 怪癖（返回 null）误报。真实站点每个 demo 渲染进独立 `#demoBody`、打开新术语重建容器，重复 id 从不共存，故不影响。

> 退出码：全部通过 `0`，有失败 `1`，脚本加载失败 `2`。CI / 部署前门禁应非零即阻断。

## 2. 人工 Review 项（自动化难覆盖，需人眼）

### 2.1 概念重复（同名 or 近义撞车）

- **精确重名**：脚本已查（`verify` 第 2 项）。
- **近义撞车**：脚本查不出，靠人判。重点扫：
  - 同分类内名字共享核心词（如「进入 / 退出 / 强调」vs「退出动画」vs「动画强调效果」——属「总览 + 细分」分工，保留；但需确认分工清晰不冗余）。
  - 注意 `name` 用 `/` 分隔的是**有意同义词合并词条**（如「行距 / 行间距」「衬线 / 无衬线」「字间距」），不是重复。
- 判定规则：若两词**释义高度重叠、用户无法区分该查哪个** → 合并（保留规范 id，把更丰富版升级进正文，删重复 id + 其孤立 demo/extra）。

### 2.2 分类合理性

- 标准 10 类：软件功能 / 字体与配色 / 输出与放映 / 图形与图示 / 设计原则 / 排版与布局 / 效率与技巧 / 动画与切换 / 母版与版式 / 图片与多媒体。
- 重点盯「软件功能」——历史上是大杂烩，新词若属「母版与版式」「图片与多媒体」维度，应直接归到那两类而非塞进软件功能。
- 分类顺序由 `app.js` 按 `data.js` 词目首次出现动态生成，导航顺序可能跳。若要整齐，在 `app.js` 加分类顺序白名单（低风险小改）。

### 2.3 demo 交互覆盖（人工点一遍）

- 自动化已确保「每个按钮点击不报错」，但**视觉效果/对齐/文字**仍需人眼在浏览器（含手机）确认。
- 历史真 bug 范例：`center-sym`（中心对称）左对齐时文本未左对齐 → `textAlign` 不能取 `flex-start`（非法）。修法：`alignItems` 取 `flex-start`、`textAlign` 取 `left`，二者拆开。
- 移动端字体：衬线栈必须显式含中文衬线（`--font-serif` 已统一），否则 Android 把 `serif` 回退成无衬线。

## 3. 新增术语标准工序（避免重踩旧坑）

每加 1 条术语，三处配套齐全：

1. **`data.js`**：对象块追加。字段顺序 `id/name/alias/category/level/summary/detail/scenario/related/demo`。
   - `related` **只引用已存在的 term id**（先跑 `node -e` 列出全部 id 再选，别凭记忆猜 id）。
   - `demo` 字段值 = 下面第 3 步的 demo 函数名。
2. **`terms-extra.js`**：追加 `'<id>': { pitfall, mnemonic, shortcut?, combo?, etymology?, checklist? }`。
   - `pitfall` + `mnemonic` **必填**，其余可选。
   - `shortcut` 为结构化对象 `{ win, mac, menu }`（字段均可省略）：`win`=Windows 键盘快捷键，`mac`=Mac 键盘快捷键，`menu`=菜单路径；菜单型术语只填 `menu`，键盘型补 `win`/`mac`。
3. **`demos.js`**：在末尾 `};` 前追加 `'<id>'(c) { ... }` 方法（注意是**方法简写** `'id'(c)`，不是 `const id=`）。
   - 渲染模式：`c.innerHTML = ...` + 内部 `function render(m){}` + 按钮 `data-m` + `c.querySelectorAll('[data-m]').forEach(b => b.onclick = () => render(b.dataset.m))`。
   - 初始 `render('某模式')` 必须对应一个真实分支。
4. **收尾必跑**：`node --check` 三文件 → `node tests/verify_ppthub.js` → `node tests/demo_runtime_test.js`（带 NODE_PATH）。
5. 文件闭合约定：`data.js` 末条无逗号 + `];`；`demos.js`/`terms-extra.js` 末条无逗号 + `};`。插入新块时先给上一末条补逗号。

## 4. 历史事故档案（踩过的坑，记入防复犯）

| 事故                    | 现象                 | 根因                                                     | 修复 / 防御                        |
| --------------------- | ------------------ | ------------------------------------------------------ | ------------------------------ |
| 重复 name（动画刷/排练计时/字间距） | 列表出现两条同名           | 新增时凭记忆猜 id，与既有 `anim-painter`/`rehearse`/`tracking` 撞名 | `verify` 第 2 项查精确重名；新增前先列全部 id |
| related 悬空            | 点 related 跳空       | 新增时 `related` 引用了不存在的 id                               | `verify` 第 5 项；新增前核对 id 清单     |
| demo 插入对象外            | 整页白屏 / 语法错         | 新函数插到 `const DEMOS={}` 的 `};` 闭合之外                     | 闭合处加逗号再插；`node --check` 拦截     |
| 居中 demo 文本不左对齐        | 短横线左对齐、文本没跟        | `textAlign` 取了非法的 `flex-start`                         | `alignItems`/`textAlign` 拆开取值  |
| 衬线移动端变无衬线             | 手机上「衬线」显无衬线        | 字体栈无中文衬线，Android 回退无衬线                                 | 统一 `--font-serif`（含跨平台中文衬线栈）   |
| jsdom 重复 id 误报        | demo 测试报 16 个 null | body 累积重复 id 触发 jsdom querySelector 怪癖                 | 测试每个 demo 前清空 `document.body`  |

## 6. 真实案例「动手试试」制作范式（CASES 库）

> 把「动手试试」从占位色块换成**真实中文 PPT 内容**。所有真实案例 demo 共用顶部 `const CASES` 库，禁止在单个 demo 里硬编码假内容。本范式由 2026-07-29 的批量改造沉淀，并已调整为「案例内容进入页面本体，顶部不再露出案例控件」。

### 6.1 共享案例库 CASES

`demos.js` 顶部 `const CASES = [...]`（当前 42 条真实中文 PPT 案例，覆盖年度复盘 / 新品发布 / 读书分享 / 项目启动 / 渠道会 / 医疗质效 / 供应链 / 会员增长 / ESG / 招聘 / 财务 / 文旅 / SaaS 等场景）。每条字段：

- `title` 主标题 / `subtitle` 副标题 / `part` 章节号 / `partName` 章节名
- `points` 要点数组 / `tw` 两栏对比 `{a,b,aPts,bPts}` / `body` 正文
- `footer` 页脚 / `kicker` Logo 字 / `img` 呼应真实图片（CC 免费可商用，见 `ppthub/` 下 `*.jpg`）

各 demo 引用 `CASES` 渲染，保证全站案例内容一致、可一处维护。加新案例只改 `CASES` 一处。完整 PPT 页面 demo 应优先用术语 id 稳定分配案例，避免同一批术语反复撞文案。

### 6.2 DEMOS 函数范式

```js
'term-id'(c) {
  const cs = pickCaseForDemo('term-id');       // ① 按术语稳定选一个真实案例
  c.innerHTML = `…完整 PPT 页面 / 模式按钮 / 操作控件…`;
  function render(m){ /* 用 cs.title/subtitle/points/body/img 渲染完整页面 + 动手交互 */ }
  render('默认模式');
  c.querySelectorAll('[data-m]').forEach(b => b.onclick = () => render(b.dataset.m));
}
```

- **案例顶栏**：不要在 demo 顶部露出「案例：…」文本标签或「↻ 换一个真实案例」按钮；`app.js` 的 `stripDemoCaseControls()` 会兜底清理旧 demo 里的这类控件。
- **完整页面优先 + 统一 SVG 范式**：设计原则、排版布局等视觉概念优先渲染 16:9 PPT 页面案例，而不是孤立色块或抽象小组件。**一律用 `<svg viewBox="0 0 960 540" width="100%" height="100%">` 包进 `.mini-slide` 容器**（`width:100%; aspect-ratio:16/9`），移动端靠 SVG `viewBox` 自动按比例缩放。**禁止用纯 HTML/CSS（div + CSS grid + 固定 px 字号）写完整页**——小屏会挤/溢出，破坏统一缩放。写法参考 `buildRepetitionSvg(cs, mode)`。
- **动手交互**：滑块/切换/选择等，按钮属性 `data-m/data-f/data-p/data-s`，运行时测试逐个点击。
- **反模式**：文本对齐用 `textAlign:left/center/right`（禁止 `flex-start`，非法）；衬线栈必须含中文衬线（`--font-serif`）。

### 6.3 测试

`demo_runtime_test.js` 自动点 `data-m/g/a/op/c` 按钮；`rule-of-thirds`(data-p)、`symmetry`(data-s) 等非常规属性需专项点击校验。目标：0 报错、0 空渲染。浏览器验收时额外确认 demo 中不再出现「案例：」或「换一个真实案例」。
